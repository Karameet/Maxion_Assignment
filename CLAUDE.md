# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity **6000.3.12f1** (Unity 6.3) 2D project using URP 17.3. It is currently a skeleton: only `Assets/Scenes/SampleScene.unity` exists and no game scripts or assembly definitions have been written yet. Game code will compile into the default `Assembly-CSharp` unless you add `.asmdef` files.

## Building and testing

No build scripts or CI exist. Everything goes through the Unity Editor:
- **Open / compile:** open the project folder in Unity Hub with editor 6000.3.12f1. Scripts compile when the editor regains focus.
- **Tests:** Unity Test Framework 1.6 is installed, but there are no test assemblies yet. Run tests from Window > General > Test Runner, or headless:
  ```
  "<UnityEditorPath>/Unity.exe" -batchmode -projectPath . -runTests -testPlatform EditMode -testResults results.xml [-testFilter <FullyQualifiedTestName>]
  ```
  Batch mode will not start while the project is open in another editor instance.
- `*.csproj` / `.sln` files are generated by Unity (the Visual Studio or Rider IDE package). Don't edit them by hand.

## Third-party stack

How these libraries fit together is the main architectural decision in this repo:

| Library | Source | Purpose |
|---|---|---|
| **VContainer** 1.19.0 | UPM git URL in `Packages/manifest.json` | Dependency injection (`LifetimeScope`, `IContainerBuilder`, entry points) |
| **UniTask** | UPM git URL | Allocation-free async/await (`UniTask`, `UniTaskVoid`) |
| **VitalRouter** 2.8.0 | NuGet via NuGetForUnity → `Assets/Packages/` | Command/message routing (`[Routes]`, `ICommand`, `Router`). Includes a Roslyn source generator (`analyzers/dotnet/roslyn/cs`) |
| **DOTween** | Asset in `Assets/Plugins/Demigiant/DOTween` | Tweening. Settings are in `Assets/Resources/DOTweenSettings.asset` |
| **Input System** 1.19 | UPM | `activeInputHandler: 1`, so only the new Input System is enabled. The legacy `UnityEngine.Input` API will throw. Action map: `Assets/InputSystem_Actions.inputactions` |

Notes:
- VitalRouter's Unity integration with VContainer and UniTask is gated behind scripting define symbols and extra UPM packages. Check that they are set up before using `builder.RegisterVitalRouter(...)` or UniTask-based handlers.
- To add or update NuGet packages, use NuGetForUnity (menu **NuGet > Manage NuGet Packages**). It writes `Assets/packages.config` and installs into `Assets/Packages/` as configured in `Assets/NuGet.config`. Don't edit those folders by hand.
- If you add `.asmdef` files, they must reference `VContainer`, `UniTask`, `DOTween` (the DLL, via precompiled references or an asmdef in DOTween Modules), and the `VitalRouter.dll` precompiled assembly.

## Repo conventions

- Commit every asset together with its `.meta` file. Unity GUIDs live in the `.meta` files, and losing one breaks references in scenes and prefabs.
- Binary assets go through Git LFS (see `.gitattributes`).
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, and `.vs/` are local editor state. Don't commit them.
